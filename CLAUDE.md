# classydms — project context for Claude / future contributors

This file gives context for AI assistants and future contributors
picking up this codebase. For end-user documentation, see the pkgdown
site at <https://mljaniczek.github.io/classydms> and `README.md`.

## What this package does

`classydms` is an R package implementing an end-to-end pipeline for
disease vs control classification from Gas Chromatography Differential
Mobility Spectrometry (GC-DMS) data. Each subject’s GC-DMS spectrum is a
2-D image of ion intensity over retention time (RT) and compensation
voltage (CV). Peaks in this image correspond to volatile organic
compounds (VOCs); the hypothesis is that disease alters the VOC
signature in a way that can be detected by a classifier and used to
nominate candidate biomarker compounds.

The fundamental challenge is **small clinical sample sizes** (~100-200
subjects per disease) combined with large per-sample data (~10^5 pixels
of structured signal). Conventional deep learning approaches overfit
catastrophically at this n/p ratio.

The package’s answer is **self-supervised pretraining on synthetic
data**: estimate the peak parameter distributions from real samples
(label-agnostic), generate millions of parametric synthetic GC-DMS
images matching those distributions, train a ResNet-style encoder on a
denoising autoencoder task with those synthetic images, then transfer
the frozen encoder to a tiny elastic net classifier on the 64-dim
global-average-pooled features. The elastic net coefficients identify
which encoder channels are predictive; weighted spatial activations
produce a saliency map in (RT, CV) coordinates that can be
cross-referenced with compound libraries to nominate biomarker
candidates.

## Pipeline at a glance

    raw .xls -> read_dms_file -> load_dms_directory  (returns samples + y)
           -> process_one_sample (SG + AsLS)
           -> baseline_basement (dust threshold)
           -> trim_bounds_from_occupancy + pooled_trim_bounds + trim_sample
           -> normalize_sample (log + quantile)
           -> pad_to_target (multiple of 32 for stride compatibility)
       ===
           -> estimate_peak_params (label-agnostic)
           -> generate_one_synthetic / generate_synthetic_dataset
           -> pretrain_denoising_online (writes encoder.pt + autoencoder.pt + manifest)
       ===
           -> cv_encoder_elastic_net          (interpretable classifier)
           -> extract_encoder_features        (or feed to your own classifier)
           -> aggregate_saliency_masked       (CAM via elastic net coefs)
           -> map hotspots to (RT, CV) -> compound libraries

## Key design decisions, with rationale

### Preprocessing

- **Savitzky-Golay smoothing along RT only** (not CV): RT has dense
  sampling (~1500 points), CV has ~50 voltage steps. Smoothing across CV
  would merge adjacent peaks.
- **AsLS baseline correction** (Eilers & Boelens 2005), not polynomial
  or rolling-ball: it handles the wide range of peak widths
  simultaneously present.
- **Per-sample relative dust threshold** = 1% of Q_0.95 of positive
  pixels: robust to inter-sample / inter-instrument intensity
  differences that a fixed global threshold would mishandle.
- **Pre-thresholded matrix retained** as `sample$Z_pretrim` for accurate
  peak-width estimation later: dust thresholding zeros out peak flanks,
  which would bias FWHM measurements narrow.
- **Cohort-wide trim bounds via robust quantiles** (q_lo=0.05,
  q_hi=0.95): one outlier sample doesn’t force the cohort to lose
  content nearly all others have.
- **Padding to multiple of 32**: matches total RT downsampling factor
  through the encoder (4 × 2 × 2 × 2 = 32), so spatial dims work out
  cleanly.
- **Center placement when padding** (not top-left): convolutional
  filters encounter zero-padding equally on all sides.

### Synthetic generation

- **Label-agnostic**: peak distributions are pooled across all samples
  regardless of class. This is the safeguard against information leakage
  from the synthetic pretraining stage into downstream classification.
- **Log-normal fits for sigma and intensity**: right-skewed,
  positive-only quantities that empirically match the data.
- **`norm_clamp = 10` safety bound** on normalized synthetic pixels:
  rare sparse synthetic images can have near-zero Q_0.95 after
  log-transform, which would blow up the normalization denominator. The
  clamp keeps such outliers from destabilizing training.
- **`size_jitter = 0.6` per-peak log-normal scale factor**: adds size
  diversity beyond what the fitted sigma distributions alone provide.
  Exposed as a function parameter (default 0.6).

### Pretraining

- **Online generation via `pretrain_denoising_online`**: memory cost is
  constant (one batch at a time) regardless of total samples seen. Lets
  the model see hundreds of thousands to millions of unique synthetic
  samples on a laptop. The batch trainer (`pretrain_autoencoder`) is
  kept for small-scale experiments and as a clearer reference
  implementation.
- **Gradient clipping** at L2 norm 1.0: prevents outlier batches from
  destabilizing optimization.
- **Fixed validation set** (`val_n = 200` by default) held constant
  across epochs: gives a stable progress metric the otherwise-random
  online training loss can’t provide.
- **Every-epoch save** of encoder + autoencoder + manifest: ensures a
  mid-run crash always leaves recoverable artifacts.
- **Periodic numbered checkpoints** (`checkpoint_every`): roll back to a
  specific earlier epoch if needed.
- **`resume_from` parameter**: pick up training from an interrupted run,
  inheriting prior loss history. Caveat: Adam moments are NOT restored.

### Classification

- **Encoder feature extraction (GAP) → elastic net** is the recommended
  path, not a neural network classifier head. With 64 features and ~200
  samples, regularized logistic regression is well-conditioned,
  interpretable, and stable. The NN head path (`cv_pretrained_oof`) is
  retained for comparison but has been less reliable in practice.
- **Deep-clone encoder per fold** inside `build_pretrained_classifier`:
  R torch’s `nn_module` objects are reference-based. Without the deep
  clone, multiple CV folds share the same encoder state, and any
  `unfreeze_last_block = TRUE` fine-tuning leaks across fold boundaries
  (we observed AUCs of 0.99+ from this bug).
  `encoder$clone(deep = TRUE)` is non-negotiable here.

### Interpretability

- **CAM via elastic net coefficients**, not Grad-CAM: because the
  elastic net classifier head is linear in the GAP features, the
  saliency map S_i(h, w) = sum_c(beta_c \* F_i^(c)(h, w)) is
  mathematically equivalent to CAM with elastic net coefs as head
  weights. No backprop required.
- **Masked aggregation across samples** (`aggregate_saliency_masked`):
  the data/padding boundary creates artifact stripes if you naively
  average. Mask by each sample’s original (non-padded) dims and divide
  pixel-wise by the per-pixel count.

## Critical lessons learned (read this if classifier AUCs look suspicious)

1.  **Cross-fold encoder leakage** — `nn_module` objects are
    reference-based. Multiple folds sharing the same encoder is a silent
    bug that can produce AUCs in the 0.95+ range that look real but are
    leakage. Fixed by `encoder$clone(deep = TRUE)` in
    `build_pretrained_classifier`.
2.  **NA noise on aggressive dust thresholds** — when `basement_thr` is
    larger than `robust_eps`, no pixels fall in the (0, eps\] range, so
    the noise estimator collects no samples and returns NA. Synthetic
    generation then produces NaN tensors. Fixed by fallback to 0.1% of
    median peak intensity in `estimate_peak_params`, plus a
    belt-and-suspenders check in `generate_one_synthetic`.
3.  **Sample-level metadata leakage** — sample-level statistics (RT
    length, total signal, mean intensity) can themselves separate
    classes in some cohorts (e.g., acquisition-batch confounders). If
    AUC on encoder features is high but you can’t find spatial saliency,
    check the metadata first.
4.  **Encoder mode collapse** — on some runs, only a handful of the 64
    encoder channels carry meaningful per-sample variance after GAP.
    Elastic net then inflates near-zero-variance “phantom” channels into
    apparent importance. Diagnose by inspecting feature variances:
    `apply(elnet$features, 2, var)`. Mitigations: longer pretraining,
    larger `size_jitter`, more synthetic diversity.
5.  **R session crashes during long pretrain runs** on Apple Silicon —
    sometimes due to memory pressure or MPS issues. Mitigations:
    [`gc()`](https://rdrr.io/r/base/gc.html) between epochs, every-epoch
    save, `resume_from` for recovery.

## Open questions / outstanding work

- **AKI vs Flu disparity** — preliminary experiments showed Flu AUC
  ~0.78 vs AKI AUC ~0.48 with the same encoder. This may indicate Flu is
  exploiting a cohort-specific artifact rather than chemistry. Needs
  more disease settings to establish a baseline of what “real biology”
  looks like.
- **Grad-CAM** as an alternative interpretability path — would be useful
  to compare to the CAM-via-elastic-net approach on the same encoder.
- **Two-channel (POS + NEG) fusion** — currently only POS is used.
  Negative-channel information may be complementary.
- **Sensitivity analysis on preprocessing parameters** — SG window, AsLS
  λ, dust threshold, trim occupancy thresholds. Currently all hand-tuned
  defaults; the existing `sensitivity_analysis_peak_params` framework
  could be extended.
- **Cross-disease pretraining** — pretrain on a pooled multi-disease
  cohort instead of (or in addition to) parametric synthetic data.

## Potential optimizations (not yet implemented)

### Parallel synthetic data generation

The `generate_one_synthetic` loop inside `pretrain_denoising_online`’s
`generate_batch()` is serial in R. On CPU runs this is ~30-40% of wall
time. On MPS runs (where GPU forward/backward is fast) it becomes a
larger relative fraction — possibly ~50% on M-series Pro/Max chips.

A fork-based parallelization via
[`parallel::mclapply`](https://rdrr.io/r/parallel/mclapply.html) would
give a ~2-4x speedup for the data-generation portion. Implementation:
replace the `for` loop in `generate_batch()` with
[`parallel::mclapply`](https://rdrr.io/r/parallel/mclapply.html) (Unix/
macOS only; Windows would need
[`parallel::parLapply`](https://rdrr.io/r/parallel/clusterApply.html)
and a cluster). Need to be careful about RNG seeding so each fork
produces independent samples — `mc.set.seed = TRUE` handles this.

Not implemented yet because: (a) on CPU the speedup is partial since
torch already parallelizes the bigger chunk; (b) on MPS the run is
already fast enough that wall-clock isn’t a blocker; (c) adds
platform-specific complexity. Worth revisiting if scaling to \>5M
synthetic samples or if users on Windows need it.

### Larger batch sizes on MPS

Default `batch_size = 32`. M-series GPUs (especially M4 Max with 40 GPU
cores) can comfortably handle 64 or 128 with substantial throughput
gain, because GPU kernel launch overhead amortizes better on bigger
batches. Activity Monitor GPU utilization \< 70% during training is a
signal there’s headroom. Increase batch size, halve `steps_per_epoch` to
keep total sample count constant.

### Mixed precision

Could enable float16 (or bfloat16) on MPS for further speedup and memory
savings. R torch supports `torch_half()` but the autoencoder hasn’t been
tested in mixed precision. Numerical stability of the denoising MSE loss
in fp16 is a concern — would need careful validation. Not currently a
priority given MPS-fp32 is already fast.

### Pre-allocated batch buffer

`generate_batch()` allocates fresh `clean_arr` and `noisy_arr` R arrays
every call. For a million-sample run that’s 31k+ allocations. Reusing a
pre-allocated buffer would shave a small fraction of wall time and
reduce GC pressure. Marginal but easy.

### `pretrain_denoising_online()` as `pretrain_denoising_*()`

The function is getting long. Could split out the
manifest/checkpoint/save logic into a helper function and the training
loop into another, making each component easier to test and modify. Not
urgent.

## Code conventions

- **roxygen2** for all exported functions with `@param`, `@return`,
  `@export`. Internal helpers get `@keywords internal`.
- **Namespaced calls**
  ([`torch::torch_tensor`](https://torch.mlverse.org/docs/reference/torch_tensor.html))
  preferred over [`library()`](https://rdrr.io/r/base/library.html)
  imports inside functions — easier to debug, more explicit.
- **Snake_case** for function and parameter names.
- **No tidyverse in `R/`** — tidyverse packages are in Suggests for
  vignettes only. R/\*.R uses base R + purrr (for `map_dbl` etc.).
- **[`globalVariables()`](https://rdrr.io/r/utils/globalVariables.html)
  in zzz.R** to silence false-positive R CMD check notes about torch’s
  `..` and `self`.
- **`.Rbuildignore`** keeps `sampledata/`, `*.pt`, `*.Rdata`,
  `_pkgdown.yml`, `docs/`, `.github/` out of the package tarball.

  be ignored.

## Notes for future Claude sessions

- The pipeline is **end-to-end working** on the influenza sample data as
  of the most recent commit. If something breaks, run
  `tests/testthat/test_loader_smoke.R` first to isolate which stage.
- **Always re-run `devtools::document()` after changing roxygen
  comments** so `man/*.Rd` and `NAMESPACE` stay in sync. The pkgdown
  GitHub Action will fail check if they don’t.
- **MPS is the right device on Apple Silicon.** Don’t try to “fix” the
  slow CPU runs — that’s just the wrong device.
- **The deep clone in `build_pretrained_classifier`** is critical. Do
  not “optimize” it away.
- **The dust threshold / noise NA path** in `estimate_peak_params` has
  caused crashes twice in development. Don’t simplify the fallback
  logic.
- The Influenza vs AKI discrepancy is a **known open question**, not a
  bug. Future analyses on more disease cohorts will help resolve whether
  it’s biology or artifact.
