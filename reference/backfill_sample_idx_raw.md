# Backfill sample_idx_raw and sample_names on an older peak_params

`sample_idx_raw` and `sample_names` were added to
[`estimate_peak_params()`](https://mljaniczek.github.io/classydms/reference/estimate_peak_params.md)
in a recent commit. `peak_params` objects saved before then lack these
fields and cannot be used with
[`build_peak_catalog()`](https://mljaniczek.github.io/classydms/reference/build_peak_catalog.md)
directly. This helper reconstructs `sample_idx_raw` from the per-sample
peak count already stored in `n_peaks$values` and optionally attaches
`sample_names` from a user-supplied vector.

## Usage

``` r
backfill_sample_idx_raw(peak_params, sample_names = NULL)
```

## Arguments

- peak_params:

  An older `peak_params` object missing `sample_idx_raw`.

- sample_names:

  Optional character vector of sample names. Must have length
  `n_samples`. If `NULL`, `sample_names` is not attached (the catalog
  doesn't need it; only the peak-params report does).

## Value

A `peak_params`-shaped list with `sample_idx_raw` and (if provided)
`sample_names` added.

## Details

Peaks in the `_raw` vectors are stored in sample-then-detection order
(all of sample 1's peaks, then all of sample 2's peaks, ...), and each
sample contributes exactly `n_peaks$values[i]` entries. The
reconstruction is `rep(1:n_samples, n_peaks$values)`.

Sanity-checks that `sum(n_peaks$values) == length(rt_loc_raw)`; if this
fails, the peak_params object is inconsistent and must be regenerated by
rerunning `estimate_peak_params`.
